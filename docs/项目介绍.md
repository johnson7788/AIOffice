# AI Office SASS项目介绍

> 一个可以直接在浏览器里使用的多租户 AI 办公套件：**文档 · 幻灯片 · 表格 · PDF · Markdown（含思维导图）** 五大原生编辑器，配一个贯穿始终的 AI 助手，一句话即可生成整套文档，并在编辑器里边聊边改。

---

## 一、这是什么

AI Office 是一套面向团队与个人的 **在线智能办公 SaaS**。它把传统 Office 的五类文档编辑能力搬进浏览器，并在每个编辑器内嵌入一个真正能"动手"的 AI 助手——不是只会聊天，而是能直接读写你的文档内容、插入图表与配图、生成整套演示文稿。

与常见"套壳型 AI 办公工具"最大的不同在于一条核心设计原则：

> **编辑引擎全部在浏览器端运行，后端只做鉴权、存储、模型代理与搜索代理。**

这意味着文档的排版、渲染、格式解析、增量修改都发生在用户的浏览器里，服务端保持"薄"。它带来三个直接好处：

- **响应快**：编辑操作无需往返服务器；
- **易扩展**：后端无状态、可水平扩展，成本低；
- **数据可控**：原生 `.docx / .pptx / .xlsx` 文件原样存储，改动是窄增量补丁，版本可回溯。

## 二、为什么做它

项目从桌面版 **genoffice**（Electron，Apache-2.0）移植而来，并在移植中做了减法：**弃用 ONLYOFFICE、OpenSandbox 沙箱以及旧的 office-op 轮询桥**。

关键洞察是——genoffice 的编辑能力本就活在渲染层（浏览器技术栈）：文档用 Tiptap、表格用 Univer、幻灯片用 canvas、PDF 用 pdf.js。因此"移植成 SaaS"并不需要重写编辑器，只要把它原来依赖的两个桌面接口（`window.desktop` 文件接口、`window.projectApi` 工程接口）用浏览器适配器改成走 HTTP/SSE + 对象存储，渲染层代码几乎原样保留即可。后端因此得以保持轻量。

## 三、核心能力

### 1. 五个原生编辑器

| 编辑器 | 技术底座 | 说明 |
|---|---|---|
| 文字文档 | Tiptap + docx-engine | 富文本，原生 `.docx` 存取 |
| 演示文稿 | canvas + pptx-engine | 幻灯片渲染与编辑，原生 `.pptx` |
| 数据表格 | Univer + Rust `xlsx-sidecar`（calamine + ironcalc）| 公式、透视表、图表 |
| PDF | pdf.js + pdf-lib | 浏览、页面编辑、导出 |
| Markdown / 思维导图 | TipTap + Markmap | 「大纲 / 导图 / 分屏」三视图，思维导图本质是 Markdown 大纲 |

### 2. 对话式 AI 生成与编辑

- **一句话成稿**：在首页描述需求，直接生成整套文档 / PPT / 表格 / 思维导图；
- **Agent 边聊边改**：每个编辑器内嵌 AI 面板，基于 ReAct 循环的 Agent 在浏览器内调用一组"技能工具"操作文档——按块读写、插入/修改图表、插图、生成整套演示文稿；
- **模型即插即用**：后端通过 litellm 代理，支持 10 家 provider（deepseek / claude / openai / google / 阿里 / siliconflow / modelscope / 豆包 / vllm / ollama），模型 key 只存服务端。

### 3. 技能中心与我的图库

- **技能中心**：可插拔的"扩展技能"体系（指令优先 + 渐进式披露），新用户注册即内置一个「去 AI 味」示例技能；
- **我的图库**：按用户隔离的私有图库，支持上传、从文档中提取图片、一键插入到编辑器。

### 4. 多租户与协作

- 注册即自动创建独立组织（租户），数据强隔离，跨租户访问一律 404；
- **单写锁**避免并发覆盖、**只读分享链接**、**版本历史与回滚**、**配额与限流**一应俱全。

## 四、技术架构

```
浏览器（编辑引擎 + AI Agent）
        │  HTTP / SSE
        ▼
   薄后端 FastAPI ── litellm 模型代理 ──► 各大模型 provider
        │                └─ SearXNG 搜索代理
        ├─ PostgreSQL（元数据 / 多租户）
        ├─ MinIO / S3（文档 blob，本地开发退化为文件系统）
        └─ Rust xlsx-sidecar（表格读算，NDJSON over stdio）
```

| 层 | 技术 |
|---|---|
| 前端 | React + Vite（npm workspaces monorepo），Tiptap / Univer / canvas / pdf.js / Markmap |
| 后端 | Python 3.13 + FastAPI + SQLAlchemy(async) + litellm + uv |
| 数据 | PostgreSQL + MinIO/S3（本地可退化为 sqlite + 文件系统） |
| 表格引擎 | Rust sidecar（calamine + ironcalc） |
| 搜索 | 自建 SearXNG |
| 部署 | docker compose（nginx + backend + postgres + minio），`k8s/` 有 k8s 骨架 |

前端 SSE 传输契约与后端 `/ai/stream` 逐帧对齐（delta / tool-call / done / error），工具在浏览器执行，后端只转发文本与解析出的工具调用意图。

## 五、目录结构

```
├─ frontend/           # 前端 monorepo
│  ├─ apps/            #   docs / slides / sheets / pdf / markdown 五个应用
│  └─ packages/        #   agent-core / ui / pptx-engine / docx-engine / ai-search 等共享包
├─ backend/            # FastAPI 薄后端
│  ├─ app/routers/     #   auth / documents / projects / sheets / skills / sharing / assets
│  ├─ app/seed/        #   注册即种子的示例文档与技能
│  └─ xlsx-engine/     #   Rust 表格 sidecar 源码
├─ e2e/                # Playwright 端到端测试 + serve.py 测试反代
├─ k8s/                # k8s 部署骨架
├─ docs/               # 文档（架构 / 部署 / 计划 / 本介绍）
├─ start.sh / kill.sh  # 本地开发一键启停
└─ deploy.sh, docker-compose.yml
```

## 七、快速上手

```bash
cp .env.example .env    # 填 MODEL_PROVIDER/MODEL_NAME + <PROVIDER>_API_KEY，改 JWT_SECRET
./start.sh              # 后端 :8585 + 五个前端 vite dev（主入口 http://localhost:3585）
```

生产用 `./deploy.sh`（docker compose 一键起 nginx + backend + postgres + minio）。
更完整的开发、部署、测试与配置说明见 [`README.md`](../README.md)、[`docs/architecture.md`](architecture.md)、[`docs/deploy.md`](deploy.md)。

## 八、适用场景

- 需要**私有化部署**、模型可自选的团队智能办公平台；
- 希望"一句话生成 + AI 边聊边改"的文档 / PPT / 报表 / 思维导图工作流；
- 想在自研产品中集成一套**浏览器端运行、后端轻量**的多格式文档编辑与 AI 能力。
